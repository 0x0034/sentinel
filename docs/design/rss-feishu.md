# RSS 公告与飞书通知服务

状态：已完成实现、验收与镜像发布；指定 RSS 的 403 限制仍存在，见 [验收记录](../verification/2026-10-22.md)。最后更新：2026-10-22。

## 目标与已确认约束

- 使用 Go **1.27.2**，采用惯用的 Go 项目结构；本地检查与 Docker 构建均固定该版本。
- 监测 `https://rsshub.app/aliyun/notice/2`，向飞书机器人发送增量通知与昨日汇总。
- 配置支持多组订阅，每组对应一个 RSS 地址和一个机器人；首组为阿里云安全公告。
- 所有增量、汇总和测试消息使用红色标题的飞书卡片。
- 需要数据库时使用 SQLite。
- 使用用户指定的机器人完成真实发送测试。Webhook 仅通过运行时环境变量提供，不写入仓库、镜像、设计文档或日志。
- 交付 `linux/amd64` Docker 镜像，并推送到 `registry.cn-hangzhou.aliyuncs.com/0x0034/` 命名空间。
- 领域术语维护在 [GLOSSARY.md](../../GLOSSARY.md)。

## 已确认的通知行为

### 增量

- 常驻服务每 5 分钟检查订阅源，增量与汇总可分别开关。
- 每个订阅第一次成功读取 RSS 时建立基线，保存已有公告但不发送历史增量通知。请求失败不能建立基线。
- 基线建立后，只为新发现的公告生成增量通知；已有公告被修改时更新保存的内容，不再次发送增量通知。
- 增量关注新发现的公告，不以发布时间必须晚于上次轮询为条件；延迟出现在 RSS 中的公告仍可被发现。

### 昨日汇总

- 每天 `Asia/Shanghai` 时区 09:00，汇总前一天 00:00（含）到当天 00:00（不含）发布的已采集公告。
- 首次启动保存的基线公告可以参与昨日汇总。
- 当天 09:00 后启动或恢复运行时，若昨日汇总尚未生成，补发该份汇总；不另行生成更早日期的汇总。
- 已经生成但未确认发送成功的任务继续重试，即使它覆盖的日期早于昨天。
- 昨天没有采集到公告时也发送卡片，明确写“未采集到昨日公告”，不宣称来源平台没有发布公告。
- 同一订阅、同一汇总日期只生成一次；重试复用原任务。生成之后新发现的迟到公告可以触发增量，但不自动重做已生成的汇总。

### 投递语义

- 失败自动重试，优先避免漏报；正常重启不重复发送已经确认成功的任务。
- 飞书已收到消息、但本地尚未记录成功时发生超时或崩溃，可能产生重复消息。用户接受此边界，不承诺严格恰好一次。
- 发送成功以 HTTP 成功状态与有效的业务响应 `code: 0` 共同判定；HTTP 200 内的业务错误仍算失败。

## 已确认的外部依赖处理

- 保留用户提供的 RSS 地址作为示例，支持在配置中替换为可访问的相同公告来源。
- 指定地址当前返回 403；本次使用明确标识为测试的 RSS 样例验证处理流程，并向指定机器人发送真实测试卡片。
- 交付报告区分“RSS 样例流程通过”“真实飞书发送通过”和“指定 RSS 当前不可达”；不得将三者合并描述为真实全链路通过。
- 生产运行需要一个可访问的 RSS 源。本轮不包括部署 RSSHub，也不自动改用阿里云上游 API。
- RSS 只暴露有限窗口；首次启动或长时间停机后，不保证补齐已经离开该窗口的公告。昨日汇总以已保存的数据为范围。

## 已确认实施方案

以下方案已获用户确认。这里的“标准架构”采用 Go 惯用目录与小包边界；Go 没有唯一的官方应用分层模板。

```text
cmd/sentinel/         程序入口、参数与依赖组装
internal/config/      读取和验证配置，解析环境变量引用
internal/feed/        HTTP 获取、RSS/Atom 解析、公告规范化
internal/store/       SQLite schema、公告、订阅状态与发送任务
internal/model/       包间共享的公告与投递数据类型
internal/notify/      卡片生成、内容拆分与飞书投递
internal/app/         轮询、汇总调度、失败重试与退出处理
testdata/             不含凭证的 RSS 样例
docs/                 设计、领域决策与操作文档
```

### 运行和配置

- 单实例常驻运行；配置在启动时读取，修改后重启生效。容器通过重启策略恢复进程。
- 提供配置示例，包含订阅稳定 `id`、名称、RSS 地址、机器人环境变量名、两种模式开关，以及全局轮询间隔、汇总时间、时区和数据库路径。
- 示例机器人凭证名为 `FEISHU_WEBHOOK_URL`；不同订阅可引用不同变量。启动时验证所有必需配置，错误信息不回显凭证。
- 订阅 `id` 隔离状态与去重记录。移动同一来源的访问地址时保留 `id`；切换为不同业务来源时使用新 `id`，建立新基线。
- 不热加载配置。机器人凭证在运行时读取，凭证轮换后重启生效。
- 提供配置检查与测试发送命令，以便验收；测试发送必须由操作人员显式调用，卡片明确标识为测试。

### SQLite 与状态

- 数据文件默认放在容器的 `/data/sentinel.db`，通过持久化卷保存。首版不自动清理历史公告和投递记录。
- 使用支持静态 Go 构建的 SQLite 驱动，减少跨平台构建对 C 工具链的要求。
- 抓取结果、基线状态与新通知任务在同一数据库事务内保存。网络调用在事务外进行。
- 公告身份优先使用非空 GUID，缺失时回退到稳定原文链接；两者都缺失的记录跳过并记录不含正文或凭证的诊断信息。
- 保存发布时间、首次发现时间和最后观测内容。缺失或无效发布时间的公告不冒充当天公告：可参与增量，排除在日期汇总之外，并产生诊断信息。
- 发送任务保存生成时的卡片内容、唯一任务键、重试次数、下次尝试时间与成功状态；分片各有独立任务键。公告后续更新不改变已生成任务。
- 重试采用有上限的指数退避；节流按机器人目标合并计算，避免多个订阅共享机器人时叠加超限。
- 单副本部署，避免把共享 SQLite 文件作为多副本协调机制。取舍见 [ADR-0001](../adr/0001-durable-notification-delivery.md)。

### 消息呈现与异常

- 卡片标题统一使用 `header.template="red"`，正文包含公告标题、北京时间、清理 HTML 后的摘要和原文链接。
- 摘要直接从公告内容提取并截断，不引入 AI 摘要服务。
- 增量通常一篇公告一张卡片；汇总按实际编码后的请求体字节数分片，包含日期和页码，留出低于 20 KB 上限的余量。
- 先处理本轮抓取，再生成到期汇总。抓取失败不推进成功状态，保留已有记录并等待下次轮询。
- 对缺乏采集记录或当前抓取失败的汇总明确提示数据范围或采集异常，避免把采集故障显示为确定的“无公告”。
- HTTP 请求设置超时、响应体上限和取消支持；日志输出订阅标识和操作结果，屏蔽 webhook、正文及凭证。
- 收到退出信号时停止产生新任务并关闭资源；未确认完成的发送保留在数据库中，下一次启动继续处理。

### Docker 交付

- 镜像名：`registry.cn-hangzhou.aliyuncs.com/0x0034/sentinel`。
- 首次标签：`0.1.0` 与 `latest`；发布前已检查，这两个标签均不存在。
- 多阶段构建，目标平台为 `linux/amd64`，使用精简运行镜像、非 root 用户、TLS 根证书与时区数据。
- 构建基础镜像采用用户指定的 `registry.cn-hangzhou.aliyuncs.com/0x0034/golang:1.27`。该镜像内置 Go 1.27.3，构建阶段通过 `GOTOOLCHAIN=go1.27.2` 固定工具链并校验版本，以同时满足用户对基础镜像和编译版本的要求。

## 验收标准

- 测试首次基线、第二次抓取新增、同一公告去重、修改不重发，以及进程重启后状态延续。
- 测试 UTC 与北京时间跨日、区间两端、没有发布时间、昨日空数据、09:00 前后启动及补发去重。
- 测试抓取 403/超时/错误 XML 不破坏基线或已保存数据。
- 测试飞书 HTTP 错误、HTTP 200 中非零业务码、响应异常、失败重试与成功任务不重发。
- 测试多订阅状态隔离、共享机器人节流，以及长内容分片后每个请求体低于大小上限且标题为红色。
- 执行 Go 格式检查、`go vet`、单元/集成测试与适用的竞态检查。
- 构建并实际运行 `linux/amd64` 镜像，以持久化卷验证重启后去重和任务恢复。
- 向用户指定的测试机器人发送明确标识的增量样例和昨日汇总样例，验证实际业务响应；不把样例当成真实阿里云公告。
- 完成镜像推送和远程架构、digest 验证。真实 RSS 的 403 状态单独记录。

## 已核实的接口和环境事实

- 2026-10-22 对指定 RSS 地址的两次常规 GET 均返回 HTTP 403，响应说明公共实例有访问限制。
- RSSHub 当前官方路由将 `/aliyun/notice/2` 映射到阿里云安全公告，仅请求第一页、最多 12 条内容。路由使用公告 ID 构造稳定链接，发布时间来自上游 Unix 毫秒值，正文来自详情 HTML；实际 RSS XML 的 GUID 尚无法核实。
- 飞书自定义机器人请求体上限为 20 KB；每机器人每分钟最多 100 次、每秒最多 5 次。标题主题支持红色。其文档未提供 webhook 消息幂等键或发送结果查询能力。
- 本地 Go 工具链、Docker 和当前 Buildx builder 可用；已成功构建、运行并推送 `linux/amd64` 镜像，远程 manifest 和架构验证通过。
