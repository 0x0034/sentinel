# 在 SQLite 中保存公告与待发送通知，接受至少一次投递

为避免服务重启丢失增量基线、重复生成昨日汇总或遗失失败通知，单实例 Sentinel 将公告更新、基线状态与新通知任务在同一 SQLite 事务中保存，投递成功后单独标记完成。相比只在内存保存游标，持久化发送任务增加了状态管理，但可以在重启后恢复未完成工作；相比引入外部消息队列，它符合项目对 SQLite 的要求。

飞书自定义机器人没有已确认可用的幂等键或发送结果查询能力，因此远端已接收、本地尚未记成功时重试可能重复发送。用户选择优先避免漏报并接受这种少量重复；系统提供至少一次投递意图，在网络和目标最终恢复的前提下持续重试，不承诺严格恰好一次。

该方案使用单副本与持久化数据卷，并以进程锁阻止同一数据库被两个服务实例同时使用。需要多副本或严格去重保证时，必须重新评估任务认领方式和接收端能力。
